### Active-phase templates (write each key to its target field)

- column_trace_capture: <purpose>
Account for EVERY active tracked column — each gets one explicit decision:
  → Continue it:  a column_flow entry mapping it to its upstream source column(s) + route upstream.
  → It ends here: a column_flow entry with upstream_columns: [] (terminal — produced here, no upstream real column).
If this node carries NONE of the tracked columns, submit column_flow: [] — it is off-trace and
the engine excludes it from the result.

A tracked column you leave out of column_flow is rejected as column_chain_incomplete —
account for it (continue / terminal). column_flow is engine-validated:
omitting the field returns ct_field_required; column_flow: [] means "no columns accounted"
and is valid only when this node has no active tracked columns (off-trace).
</purpose>

## Before submitting — verify
□ Every active tracked column appears as an out_col in column_flow (continued, or terminal with upstream_columns: []). If the node has no tracked columns, submit column_flow: [] (off-trace).
□ Each upstream_columns entry is a real INPUT to `out_col`'s value — it appears in `out_col`'s producing expression (the formula / CASE / SELECT clause that computes it). A column that sits on the same source but feeds a different output is off-trace for this `out_col`: omit it. Trace only the columns that derive the tracked target and its sub-questions.
□ sections[].text — this hop's narrative body — explains the context of the flow, including HOW the value is computed (formula / CASE / COALESCE / rename); that narrative never goes into column_flow fields.
□ sections[].text: open with focus node as subject — "[schema].[FocusNode] is ..." not "This node is the builder for `OtherNode`".
□ When an out_col is produced by a computed expression (arithmetic, CASE, COALESCE, aggregation), sections[].text includes the producing expression as a `$$ … $$` block.

## Example — column interacts (Revenue computed at vw_Sales)
column_flow: [
  { out_col: "Revenue",
    upstream_columns: [
      { node: "fact_orders", col: "Qty" },
      { node: "fact_orders", col: "PriceA" }
    ]}
]
verdict: "analyze"

## Example — this node is off-trace (carries none of the tracked columns)
column_flow: []    ← the engine excludes this node from the result

## Verdict — choose based on how the node interacts with tracked columns
- `analyze`: the node transforms or is the terminal source of a target column.
  Fill column_flow for each active column.
  Terminal (no upstream possible): upstream_columns: [] — stored base column,
  hardcoded literal, or system function (GETDATE(), NEWID()). Empty
  upstream_columns signals the branch ends here.
- `passthrough`: column flows through unchanged; the upstream writer is not yet visited.
  Fill column_flow naming the upstream column, then add route_requests to visit it.
  The edge is recorded here; full attribution resolves at the routed node.
- Off-trace: if the node carries none of the tracked columns, submit
  column_flow: [] — the engine excludes it from the trace.

## Non-bodied table focus (TABLE written by a procedure)
When the focus node is a TABLE (no DDL — only schema metadata), the procedure that
writes to it is upstream. Use verdict='passthrough'; use the column name as it appears in the table.
column_flow: [{ out_col: "OrderTotal", upstream_columns: [{ node: "[schema].[spWriter]", col: "OrderTotal" }] }]
Leave route_requests empty — the CT engine queues upstream_columns[] automatically.

## column_flow fields per entry
- out_col: column name being produced. For PROCEDURE focus: the column name in the target table (same as writes_to.col).
- upstream_columns[]: real upstream source column(s), each { node, col }. One entry per upstream input.
  Formula / CASE / COALESCE with multiple inputs: list each input separately.
- writes_to: set when the focus node is a PROCEDURE that writes to a table.
  Must be an OBJECT: { node: "[schema].[TargetTable]", col: "ColumnName" }.
  NOT a string. out_col = the column name being written; upstream_columns = upstream inputs.

## Common patterns
- Rename (upstream col name ≠ out_col): same data, different name — note the rename in sections[].text.
- Fan-out (one source → two output columns): two entries, same upstream column.
- Computed expression from two columns: two upstream_columns entries.
- Filter/lookup-only column (WHERE / JOIN-ON only, no value contribution): NOT an
  upstream_columns entry — explain it in sections[].text when it matters.
